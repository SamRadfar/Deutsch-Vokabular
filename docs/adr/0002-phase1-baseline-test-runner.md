# ADR 0002: Node's built-in test runner for the Phase 1 baseline

- Status: **Accepted** (Phase 1)
- Date: 2026-10-15

## Context

Phase 1 needs read-only regression checks for the legacy vocabulary before any
refactoring starts. The target stack (ADR 0001) uses Vitest, but no application code
exists yet, and the repository has no `package.json` and no dependencies.

## Decision

Use `node --test` (Node ≥ 22, which supports test-file globs) with **zero npm dependencies** for the baseline suite:

- `scripts/lib/legacy-source.mjs` extracts `DATA` and `BAUTECHNIK_INFO` by locating
  the object literals with a string-aware scanner and evaluating **only those
  literals** in an empty `node:vm` context. The app itself is never executed.
- The fixtures in `tests/fixtures/` are generated by scripts and never overwritten
  without `--update`. They carry SHA-256 fingerprints.
- Known legacy defects are `todo` tests: they are reported on every run without
  failing the suite.

## Consequences

- (+) `npm test` works offline right after cloning: there is nothing to install and
  no lockfile or supply-chain surface.
- (+) It runs identically in CI and locally, on Windows (CRLF is normalised) and Linux.
- (−) A second test runner will exist once Vitest arrives. The baseline tests use
  only `node:test` and `node:assert`, so porting them is mechanical. Alternatively
  they can stay as a separate `test:baseline` script.
